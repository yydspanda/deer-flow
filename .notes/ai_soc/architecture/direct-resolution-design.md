# 企业规则与审核经验直接处理

状态：已实现并通过本地组件/浏览器验证。任务归属 PI-03E；不改变 PI-01 内网验收指针。

## 用户约定

企业确定性规则先决定处置；没有决定时，精确复用 Memory 直接采用审核结论；只有两者都未决定
才执行主模型研判。运营负责审核业务规则和经验适用范围，系统负责准确执行，不再让 LLM 批准经验。
context-only 经验继续参与模型判断，仍可以使模型得到与经验一致的结论。

## 执行顺序

1. Adapter 标准化，生成企业规则需要的 canonical 事实。检查已启用、enforced 的确定性企业规则。
2. 明确命中忽略/转交：直接形成处置结果，不调用语义核对、主研判或角色复核模型。
3. 未决定：按原配置执行语义核对，重建事实；使用补充后的事实再次检查企业规则。
4. 企业规则未决定：使用现有 Profile、审核适用条件与有效期检查完整的可用精确指令集合。
   一致且可直接覆盖的审核结论直接采用；reference-only、reinforce-only 或相反指令不短路。
5. 未直接决定：正常构建模型上下文、研判、角色复核和后置策略。
6. 三条路径共用 AnalysisRun、结果持久化、决策演变、反馈、ZEUS 回传及动作授权/执行出口。

需要模型结论/场景的企业规则，在这些条件不可判断且其他条件满足时属于“尚未决定”，不能当作
未命中而越过高优先级。低优先级忽略不抢先执行。没有依赖字段时不人为制造一个模型结论。
Policy Skill 不提前冒充确定规则。精确 Memory 已直接决定时，不再调用 Policy Skill 重做研判；
确定性企业要求仍检查并保留。固定企业规则不因 Memory 放宽行为勾选范围而改变。

## 契约与边界

- AnalysisRun 增加直接处理结果：来源、版本/hash、处置、审核结论、匹配依据、企业决策快照。
- `analysis=null` 明确表示没有主模型分析；不是 stub，也不是失败。置信度允许空值，不伪造评分。
- Base 阶段标记 skipped，不伪造“先判风险、后改误报”。Memory/企业规则来源和最终结果照常可查。
- 原始告警、标准化数据和逐步耗时保留。模型调用数按真实调用计算，语义核对与主研判分开统计。
- 数据范围在企业策略预检查前绑定，不依赖被跳过的模型上下文补充步骤。列表与轨迹使用同一范围判定；早期策略直接处理结果若遗漏请求范围，只能从已保存的策略快照恢复展示，不修改结果、不重跑，也不放宽其他环境隔离。
- 精确决策检查不使用给 LLM 的 Top-K/Token 截断集合，避免截掉相反指令。
- Memory 的状态、版本、有效期、排除条件、指令类型与审核匹配范围继续由现有服务校验。
- 直接复用只累计使用，不生成新的独立研判样本或自动候选；人工反馈/修订仍可用。
- 不改变真实动作授权、目标解析、执行幂等；没有角色模型输出不伪造攻击者/受害者。
- 平安规则和配置留在 Integration；共享 Runtime 只接受通用直接处理接口。
- 默认启用新编排，可用 `SOC_DIRECT_RESOLUTION_ENABLED=false` 回到原完整研判顺序。
  企业策略原总开关、各 Provider 开关、Memory 启用开关和外部动作开关保持独立。

## 交互

主界面仍只有忽略/转交及依据。命中时显示“已按企业规则处理”或“已复用审核经验”，技术详情
显示跳过的步骤。企业规则只决定处置时，安全判断为未单独研判，不强行把转交标成攻击或忽略标成误报。
精确 Memory 保留审核安全结论；若后续人工修改，沿用现有反馈、暂停/修订经验入口。

企业规则匹配与 Memory 精确复用不是同一条件：例如 `RPAADM_000558` 的平安明确转交规则
只检查 NDR 来源与规则编码，不要求行为指纹。2026-09-15 确认保留此范围，不额外收窄。
Memory 直接复用则位于已配置的语义核对之后，使用采用后的标准事实匹配审核条件。
轨迹显示命中的规则名称、规则编码及处置决定；跳过的语义核对保持灰色，不从列表消失。
审计使用 `skipped` 区分正常跳过与失败，未调用主模型时不重建“已发送上下文”，也不补造置信度。
这些是读取已存运行结果的展示调整，不改变策略优先级、匹配范围或重新执行历史告警。

## 验收

### 告警演练的运行开关

页面的“后续运行设置”提供四个开关，无需为每次演练修改环境变量或重启：

| 开关 | 本次运行的效果 |
|---|---|
| 语义核对 | 开启时使用 LLM 补充标准事实；关闭时只使用 Adapter 结果。已被前置企业规则处理时仍正常跳过 |
| 企业策略 | 总开关；关闭后不执行企业规则、安全软件路径策略或 LLM 策略建议 |
| 安全软件路径策略 | 企业策略子项，仅控制本地安全路径目录信号，不启用真实外部能力 |
| LLM 策略建议 | 企业策略子项；仅在原编排需要该建议时调用，不强制每条告警增加调用 |

选择随 `/alerts/{alert_id}/process` 的 `settings` 提交。应用组合层为该次运行构造服务，
不修改 `os.environ`，仍共用一个工作台、并发上限及同告警运行锁。参数只允许这四项；
未配置的能力不可从页面启用，企业接口与外部动作保持关闭/模拟。

`AnalysisRun.execution_options` 在调用 Provider 前保存，执行轨迹显示“本次运行配置”。
修改页面开关只影响之后点击的运行，不重写旧结果或影响其他人。浏览器刷新保留本标签页选择，
可恢复部署默认值。无请求设置的旧客户端仍按部署默认执行，不需要数据库迁移。

### 原有链路

- 企业转交优先于误报 Memory，三类模型均零调用；规则关闭时回原链路。
- 非 200/请求失败/路径策略保持原条件、优先级与排除边界。
- Memory 精确命中主研判零调用；相似/停用/过期/版本不符/相反指令不能直接复用。
- 取消核心行为后不隐含要求旧完整 hash；附加 IP 不命中只退为参考。
- 直接处理持久化后可回读 Web、结果 API、ZEUS 格式和决策演变；不标失败或显示假置信度。
- 重放幂等；使用记录可回查；不把复用次数算成人工验证或新样本质量。
- 本地测试使用显式模拟规则/经验；真实内网回写与动作继续在原验收台账完成。

不在本轮：重写厂商规则、升级指纹分组、清库、审批旧候选、全语料付费模型重跑。

  没有为使测试变绿改旧计数或业务索引。真实模型准确率、内网回写与外部动作未在本轮验证。

**如何自己试：**在告警演练重跑一条已知命中企业转交规则的告警，结果应显示企业直接处理、主模型
未调用。要单独试 Memory，则选没有被企业规则先处理、且存在有效精确经验的告警；仍按你审核的
勾选条件执行。全开企业规则时被规则先处理，是优先级生效，不是 Memory 失效。
旧结果不会自动重写；下一次新运行才走本编排。关闭总开关只回退编排，不撤销已确认经验或规则。
