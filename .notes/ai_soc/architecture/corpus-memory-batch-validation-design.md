## 1. 最终要怎样使用

**内网脚本负责批量执行，网页负责查看、审核和少量手动复测。两批都不要求逐条点运行。**

**执行地点已确认：外网只开发和模拟验收，真实运行全部在内网 Mac DEV。**

- 外网可读取已有语料生成分批预览、核验名单和展示页面；不调用真实模型进行本专项的研判、语义核对或经验起草。
- 外网通过隔离 SQLite、模拟模型/Provider 和浏览器测试验证批跑、审核、续跑、快照与报告；模拟记录不混入现有业务库，也不作为正式实验经验交付。
- 第一批真实批跑、运营审核沉淀、第二批效果验证，以及少量无经验/有经验对照，均在内网 Mac DEV 执行。
- 用户已授权继续完成剩余流程；外网仅开发和隔离 Mock 验收，不代替运营审核经验或在内网实际提交任务。

```text
平台维护人员：检查环境、固定两批样本名单
  -> 脚本后台运行第一批：沉淀经验
  -> 运营在经验中心：查看代表告警、确认结论、编辑业务经验、设置适用范围
  -> 固定本轮已审核经验及运行配置
  -> 脚本后台运行第二批：验证效果
  -> 页面与报告：查看忽略/转交、经验使用、标签对比、耗时与模型调用
  -> 运营纠正不适用经验或新增细分经验
  -> 脚本新开一轮复测：保留修订前后结果
```

角色分工：

| 谁 | 主要操作 | 不要求做什么 |
|---|---|---|
| 平台维护人员 | 启动、暂停、续跑、排查失败、导出报告 | 不手工编辑几千条请求 JSON，不直接改业务表 |
| 运营专家 | 审核代表样本、给出最终判断和已知业务事实、确认经验使用方式 | 不逐条点击第一批或第二批运行，不填写技术 Hash |
| 系统 | 去重、调度、研判、候选协调、经验使用、结果留痕和统计 | 不自动批准经验，不把模型结论当运营真值 |

必须保留：原始数据、原始运行轨迹、人工提前提炼、相似经验参考、精确复用、企业策略优先、
经验修订/暂停/废止、已有宽窄范围治理。此次不重新设计行为指纹或改判算法。

### 3.2 前端不再等待点击时编译

- 给 SOC 启动器增加独立的前端服务方式：运营验收使用预构建产物；代码开发仍可选热更新。
- **前端预构建不等于项目切 STG。** 后端 DEV、工作台、数据库、模型、鉴权开关和 Provider 目标保持不变。
- 外网适配 SOC Docker overlay；内网适配 Mac Host 启动器，不要求内网安装 Docker。
- 构建与正常启动分开，代码或构建相关配置变化时才重新构建；记录产物对应的源版本与配置摘要。
- 构建失败不能先停掉仍可用的前端；通过后再切换。回退只切前端服务方式，不删除业务数据。
- 状态检查使用轻量健康/就绪接口，不因检查旧演练页面而触发编译；不把大量路由预热当根本修复。
- 不修改 DeerFlow 通用聊天、通用 Agent 或通用状态管理代码来解决 SOC 业务问题。

### 3.3 减少无用加载，保持审计深度

1. 告警列表每次默认 20 条，只返回列表字段；完整轨迹、正文、原始 JSON 留在详情接口。
2. 分组选择器打开后才请求目录，服务端搜索并分页，默认每页 50 组；搜索覆盖完整索引，不只搜索已加载的 50 组。
3. 不再每次附带专项演练结果。固定推荐演练入口已移除；保留原有分组样式、搜索、查看同组和返回筛选，旧结果链接仍可查阅。
4. 列表先查询本页身份，再批量查询本页关联 Run/Memory/Candidate；不将全库完整 Run 装入内存再切页。
5. 总数用数据库聚合或可重建的轻量摘要。成功运行、审核和启停后只刷新受影响数据，不静默缓存旧状态。
6. 筛选、批次、页码、展开对象和返回位置保持一致。页面离开后停止无用轮询，返回时核对最新状态。
7. 保留所有步骤的可审计内容，只改变何时读取，不删事实、不截断 Skill 或修改模型输入。

**分成两个批次不是性能修复的替代品。** 即使只看第一批，仍需上述有界查询和预构建。

### 3.4 性能验收目标

- 服务就绪后首次打开主要 SOC 页面，目标 2 秒内呈现主要内容；连续 20 次常用页面切换，目标 P95 不超过 1.5 秒。
- 以上是同一机器、同一数据规模下的浏览器端目标，包含读取和渲染；首次构建耗时单列，不掩饰到统计之外。
- 当前页列表响应目标不超过 150 KB；返回数量受分页控制，不随全库组数线性膨胀。
- 用超过 10,000 条运行/使用记录的隔离测试库验证不漏旧结果；不得通过把固定上限改成更大数字解决。
- 页面可及时看到他人运行与经验变更；返回筛选不丢失；重启状态检查不触发路由编译。
- 记录冷/热访问、查询、渲染、CPU/内存样本和硬件；内网 Mac 另测，不用外网数字代替。

## 4. 第二阶段：固定两批样本

### 4.1 划分规则

**按已有同类组，再按组内告警事件时间，划分早期积累样本与后续验证样本。不是只按 Rule Code 分组。**

| 同类组样本数 n | 第一批：沉淀经验 | 第二批 |
|---|---|---|
| n >= 6 | 前 k 条，`k = min(10, n - 1, max(5, floor(n * 0.7)))` | 剩余部分进入主要验证 |
| 2 <= n <= 5 | 不纳入默认积累批 | 全部进入补充测试，标记同类样本较少 |
| n = 1 | 不纳入默认积累批 | 进入补充测试，标记单例样本 |

例：6 条分为 5 + 1；10 条分为 7 + 3；52 条分为 10 + 42；514 条分为 10 + 504。
10条是首轮积累的工作量上限，不是产生经验的保证。既保留5条门槛的余量，也避免大组积累几百条后才审核。
恰好5条能用于提炼，但不能同时满足5条积累及至少1条独立验证，因此也标为补充测试。

- 自动积累与人工提前提炼继续共用现有学习协调和治理入口；重跑同一告警不增加独立支持次数。

- 不把直接复用的结论算成新的独立判断；不把处理失败伪装成经验样本。
- 运营仍可对一个有价值的已完成告警提前提炼，不要求先凑齐 5 条。

第一批积累作用域的 `review_mixed_conclusions` 显式允许此情况，通过现有治理服务生成
`review_kind=mixed_conclusions` 候选；普通运行不放宽。回归见
`backend/tests/test_soc_memory_experiment_accumulation.py`，不在脚本中伪造普通候选。

### 5.3 运营需要做的事情

1. 在经验中心按本实验、第一批和待审核筛选，查看实际事件、代表告警及关键差异。
2. 选择最终判断；业务事实保持可选，只填写已经知道或核实的业务情况。
3. 请求 AI 生成经验并编辑各项内容，检查判断依据、泛化边界、失效条件和处理建议。
4. 设置适用条件与未来使用方式，确认并按现有治理流程开放使用。

批量起草只针对已有运营最终判断的候选，业务事实为空时使用来源事实和该判断，不能编造审批、授权、
业务沟通或设备检查已经完成。不得覆盖正在编辑的草稿；重生成需要明确选择。
审核、开放使用和范围放宽不提供无人确认的一键全批批准。

## 6. 第二批：脚本验证，不边跑边训练

### 6.1 固定一轮输入

创建验证轮次时，保存第一批已审核、可使用的 Memory ID/版本/内容 hash/适用范围及其治理状态摘要，
并保存模型、Prompt、Profile、语义核对缓存策略、企业策略、Provider 模式等配置摘要。
第二批无权把同批新候选或其他实验的经验悄悄加入集合。

**快照不是永久授权。** 在准备调用和提交直接复用结果前仍检查暂停、废止、有效期和范围边界。
冻结集合中的经验或关联治理边界发生变化时，暂停提交新任务，标记该轮受变更影响；
已完成结果保留，进行中的调用不硬杀。需要使用变更后的经验时另开轮次，不能继续用已停用旧经验。
新经验也不静默进入旧轮次；为简化首版，对实验内会影响匹配的治理变更宁可暂停，而不猜测影响无关。

### 6.2 批跑行为

- 默认运行第二批主要验证；补充测试单独选入、单独汇总，不必全部一起跑。
- 精确且覆盖完整的经验按现有规则直接复用；部分匹配可进入模型上下文，保留未覆盖行为的机器比对说明。
- 企业策略是否参与由本轮配置决定；参与时继续保持既有优先级，不为提高 Memory 命中率改变顺序。
- 第二批保存所有 Run、MemoryUse、匹配差异、决策与耗时；默认不增加 Pattern 学习支持、不自动创建 Candidate。
- 关闭自动学习不等于关闭 Memory 使用记录。轨迹显示“已记录经验使用，本轮不积累新经验”，不能卡在等待 Pattern 完成。
- 人工提炼和修订仍可用，但新对象不加入当前验证轮次；对该告警的后续调优结果单独列为复测。

### 6.3 修订后的复测

支持选择：本轮失败项、某个 Rule Code、指定经验的实际使用告警、指定同类组、人工勾选项或完整第二批。
只重跑旧经验使用项不能证明新范围全部正确：当修订涉及范围扩大/缩小，应同时选择边界内外样本，
因为新增可匹配告警可能从未使用过旧经验。

新一轮明确关联前一轮，逐条保留 `alert_id -> old run_id -> new run_id`。页面可对比结论、使用方式、
经验版本、差异说明和耗时，不把“最新 Run”覆盖显示当作唯一批次结果。
第二批已经用于调优后，其后续结果标为复测，不能再宣称是全新未见样本验收。

已实现 `retest-plan`：只读取固定报告，按失败状态、实际使用过的Memory、规则、分组或告警ID选样。
同一筛选内多个值为“任一”，不同筛选之间取交集；`--all`显式选择旧报告全部成员，不能与筛选混用。
精确和参考使用都属于“实际使用”，仅出现在冻结经验库存中不算使用。名单保留主要/补充标签及旧Run ID，
`learn/validate --selection-file`沿用原实验、批次和父轮次；服务端校验来源与选择hash，不另起Runtime。
成功结论仍只在两边均有效时比较；失败变成功另有任务状态对照，不把失败当风险结论。
本地名单hash用于防误改，不是签名/授权；经验范围变化后的边界外样本应另外选组复测，不能冒充旧使用记录。

## 7. 页面改成两个批次，不再依赖固定 Demo

告警演练主入口仅保留：**第一批 · 沉淀经验**、**第二批 · 验证效果**。
固定推荐演练及两组故事线已先行移除；分批改造继续保留同类组浏览样式和搜索，
不把方便查看同类告警的分组功能一并移除。原演练告警仍保留在语料和搜索中。

| 页面区域 | 第一批 | 第二批 |
|---|---|---|
| 顶部摘要 | 总数、已完成/运行/失败、待审候选、已确认经验 | 当前轮次、总数、已完成/运行/失败、经验使用分布 |
| 范围选择 | 分组、规则、来源、运行状态 | 同左，增加主要验证/补充测试和结果差异 |
| 列表 | 告警、实际模式积累、候选入口、查看结果 | 告警、忽略/转交、经验使用、标签对比、查看结果 |
| 主要动作 | 查看批跑进度、去经验中心审核、单条运行/提炼 | 查看批跑进度、单条复测、查看对比、导出 |

- 脚本和页面显示同一任务、同一轮次，不分别维护“脚本结果”和“网页结果”。
- 点击详情才读取原始输入、语义补充和完整 Runtime Trace，列表不自动跳到页面底部。
- 从审核返回时保留实验、批次、分组、页码和位置；经验中心沿用现有三个视图，不新增一套审核中心。
- 默认显示全部状态，不预先隐藏已运行项。新旧轮次明确切换，同条告警可查看多轮结果。
- 沉淀进度与新告警实际使用分开：已确认一条经验不代表当前告警使用了它；参考使用也不等于精确复用。
- 同类组名称相似时显示可读关键行为、数量和短编号，完整 Hash 留在技术详情。

## 8. 后台实现：一套服务，不是第二套 Runtime

### 8.1 控制与执行分工

```text
内网批跑 CLI / SOC 网页
  -> SOC 批次 API 与薄的批次协调服务
  -> 同一 SOC SQLite：名单、轮次、任务及可恢复状态
  -> SOC 后台执行器：领取任务、租约、共享模型并发预算
  -> 既有 SocAnalysisService / Runtime
  -> 既有 Pattern / Memory 治理 / 结果与审计仓储
```

CLI 负责创建、启动、暂停、续跑和导出，不直接写候选表，也不自行构造另一套 Prompt。
批次一经受理由服务侧继续调度，不依赖保持 CLI 或浏览器连接；整机停止期间当然不执行。
服务器重启后先核对版本/配置/经验状态，再恢复已明确启动的批次；不在服务恢复时自动创建新轮次。

优先复用 `SocProcessingJob` 的持久化、幂等和租约，不新增 Celery、Redis、Kafka 或独立调度平台。
语料任务声明独立的 `workload_kind`，复用现有 `deepseek-v4-flash` 模型队列命名时，
必须先补齐按 workload 领取任务的过滤，并限定旧 ZEUS Worker 只领取其合法类型。
当前只按 queue 领取的实现不能直接混投任务；仅设置 metadata 不足以阻止错误 Worker 消费。
语料执行器不调用旧系统 lifecycle/callback，PRECHECKING 只做本地输入与配置校验。

### 8.2 拟新增的最小持久数据

所有表/协议名在实施时遵守现有命名约定并通过迁移，不由脚本临时建表。

| 对象 | 内容 | 不能替代什么 |
|---|---|---|
| 实验与样本名单 | 数据/索引 hash、划分规则、成员、时间、原组、主验证/补充类别 | 不复制原始语料或作为新的 Memory 匹配条件 |
| 执行轮次 | learn/validate、范围、配置/经验快照、状态、父轮次、操作者 | 不覆盖既有 Run 或批准经验 |
| 轮次成员结果索引 | alert/payload hash、Processing Job、attempt/run_id、阶段耗时、候选/使用摘要 | 不复制完整模型审计 JSON，不成为第二份业务真值 |
| 通用任务与事件 | 领取、续租、失败重试、恢复、结果引用 | 复用现有 jobs/events，不平行造队列 |

**第一批和第二批必须使用相容的 tenant、Memory 环境与数据使用范围。**
`batch_id`、`round_id` 只作为实验来源和查询维度，不放入行为指纹或必需匹配条件，
否则会出现第一批经验永远匹配不上第二批的错误。实验间用受控经验集合隔离，不伪造不同厂商/环境。

新服务负责批次编排，PingAn Profile 继续负责规则码和行为语义，Runtime 继续负责单条控制流。
批次不得仅靠传入旧存储元数据来伪造服务端可信环境、经验权限或外部动作授权。

### 8.3 并发、幂等和恢复

- 模型调用预算初始沿用 3，批量任务、网页研判和经验起草共用 SOC 调用额度；不对每个子脚本各开 3 个。
- 内网模型网关继续作为最终上限；普通聊天或其他服务占用需计入环境实测，不能宣称 SOC 限流覆盖未接入的客户端。
- 人工交互优先获取下一空闲槽，不抢断正在调用的模型。初始限额可调，只有运行容量改变不必重建轮次。
  已接入：显式选择单个告警的已启动轮次优先于批量轮次和后台起草（Web/CLI相同）；
  准备/暂停、尚未到重试时间、同告警正在运行的不抢占。实际模型调用按交互/后台两级FIFO等待，
  同步网页起草优先于批跑的下一次模型调用。不改并发上限；持续人工操作可能延后批跑，普通聊天等
  未接入此SOC控制器的客户端仍不在本地优先级保证内。
  外层超时不会提前释放尚未结束的本地调用名额；取消成功或本地调用真正结束后才释放，
  不为了保持满速再挤入第四次调用。远端在连接断开后是否继续计算仍只能由内网网关确认。
- 入队幂等键包括实验、轮次、alert_id、payload/config 身份；相同请求重放回读原任务，不重复收费运行。
- 同一告警在网页/CLI 同时发起时共享持久占用；同一轮次复用已有任务，其他轮次等待或明确提示占用。
- 领取与提交采用事务和租约版本检查；HTTP 请求或模型调用期间不持有 SQLite 写事务。已有幂等约束必须覆盖候选观察写入。
- Pause 停止新领取，允许已开始任务收尾；Resume 接着未完成部分。取消与强制终止分开，默认不硬杀调用。
- 已保存 Run 但尚未记账的任务恢复时先补记结果/幂等观察，不能再次调用模型；只失败于观察的重试不重复主研判。
- 进程在远端已完成但本地尚未保存时崩溃，可能无法保证模型只调用一次；记录不确定尝试并有界重试，不能宣传全链路 exactly-once。
- 429/连接抖动采用有上限的退避；配置/鉴权错误暂停批次；数据或契约错误保留失败原因，不无穷重试相同输入。
- 继承各模型节点现有重试与修复预算，批次层只处理可恢复失败，不将多层重试次数相乘放大。

### 8.4 有界查询和进度

名单及任务分块入库/领取；从 payload SQLite 按需读取，不为每个 worker 加载完整 PKL。
进度按批次聚合，客户端每隔数秒读取一个轻量摘要，不对每条告警各自轮询。
结果摘要按 run_id 幂等更新，初次回填可离线构建；单条完成不重算所有历史指标。
页面及报告从精确轮次成员读取，不能沿用 `list_runs(limit=10000)` 后挑最新的方式。
外显完成、失败、待执行、速率、预计剩余时间；预计时间根据实测速率更新，暂停时间和模型排队时间分别记录。

### 8.5 拟提供的操作面

以下操作已接入；可直接复制的参数与执行顺序见[内网两批实操手册](../integrations/pingan-corpus-batch-runbook.md)：

| 操作 | 用途 |
|---|---|
| prepare / inspect | 校验语料与索引，预览并固定名单，不调用模型 |
| learn / validate | 明确选择范围与配置，启动一轮后台任务 |
| status / pause / resume | 查询、暂停新任务、恢复原轮次 |
| retry-failed | 只重试可重试项，保留每次尝试，配置变化要求新轮次 |
| draft-candidates | 批量起草已有最终判断的候选，遵守草稿版本和不覆盖规则 |
| draft-plan / draft-status / draft-retry / draft-export | 固定运营已选判断的起草名单、查询、显式重试和独立成本报告 |
| export / compare | 导出单轮结果及跨轮逐告警对比，不调用模型 |

HTTP 新接口置于现有 SOC DEV 工作台命名空间，提供分页成员/分组、创建轮次、轻量活动和结果查询。
现有单条 process 接口兼容保留；脚本身份与网页身份通过同一授权入口，不直接打开 SQLite 修改业务记录。
内网可信演示可继续显式免登录模式；不在代码里硬编码管理员或将 DEV 身份扩大到 STG。

## 9. 配置与速度：先确定测什么

### 9.1 建议的两种实验目的

| 配置 | Memory 专项验证 | 完整流程验证 |
|---|---|---|
| 第一批经验来源 | 固定初始集合，首次为空 | 明确固定初始集合 |
| 第二批经验来源 | 第一批已审核版本 | 同左 |
| 语义核对 | 开启并用于后续研判，记录缓存命中 | 同左，或显式固定其他已批准配置 |
| 企业策略 | 建议本实验关闭，避免策略直接接管所有样本 | 开启既有规则、安全路径和 LLM 策略配置 |
| 真实模型 | 内网已配置的模型服务 | 同左 |
| 外部查询 | 默认关闭/Mock；需要时单独显式配置 | 每类真实/Mock 按清单记录 |
| ZEUS 回写与高风险动作 | 禁止 | 历史语料演练仍禁止，真实闭环另行验收 |

**Memory 专项关闭企业策略仍是待启动时确认的配置建议，不能由本方案写入自动修改当前服务开关。**
策略开启时未形成候选或未使用 Memory 是正常分支，应单列策略直接处理数，不算 Memory 失败。
改变实验目的、模型、Prompt、Profile、事实重核策略或经验集合时新开轮次；不覆盖原配置。

### 9.2 缓存与并发对速度的含义

- 相同原始输入和已核验缓存身份可复用语义事实；明确记录真实调用还是缓存复用。
- 当前经验选择与企业策略必须重新评估，不能把上次告警的最终结果当事实缓存拿来用。
- 体验吞吐可用已有缓存；要测首次处理成本，另做明确的冷缓存样本测试，不能混为一个平均值。
- 精确复用能节省主研判，不保证语义核对也可跳过。是否跳过沿用实际 Runtime 分支并记录。
- 内网 Mac DEV 默认先跑 5 条连通性与 50 条容量样本，再扩到已批准范围；外网仅模拟此流程。仍属于同一名单，不重复完成项。
- 由实测完成速率估算总时长；失败重试、经验起草、等待与主研判调用分别统计。

## 10. 结果保存与指标

### 10.1 页面与磁盘

业务真值留在同一 SOC 数据库；导出是可重建快照，不是另一套可写经验库。
项目相对目录拟定为：

backend/.deer-flow/soc-validation/memory-batch/<experiment_id>/
  README.md                     本实验范围、批次和查看入口
  dataset-manifest.json         固定名单、来源与划分规则

    summary.json                可机读统计，含分子分母与失败量
    results.csv                 每条告警一行，可用表格软件查看
    memory-usage.csv            每个使用关系一行，含版本和实际用法
    failures.csv                失败阶段、原因、尝试次数和是否可重试
    REPORT.md                   面向人阅读的结论与限制

默认不为所有告警再次复制十几份大型 JSON；完整链路仍已持久化，可按需导出一条、一组或整轮。
CSV 处理公式注入前缀，原值仍保留在 JSON；所有原始告警、SQL 数据、经验和报告按内部数据保护，Git 忽略。
路径用项目根和 `Pathlib` 解析，不写死 `/Users/zhangjianming627`。

### 10.2 第一批与第二批分别看什么

第一批看：完成/失败数量、有效观察、实际模式、产生/复用的候选、待审/已确认经验、没有候选的原因。
不以候选数量越多越好，不以模型判断相同代替运营确认。

第二批顶层只突出：处理量与失败量、忽略/转交、经验使用分布、耗时与调用。
有可信标签时显示质量比较，没有时用 `--`，把统计说明放在详情，不堆砌运营难懂的提示栏。

详细统计遵循 [效能与规则优化口径](../governance/effectiveness-and-rule-optimization.md)：

- 按 Rule Code/通用检测身份、实际行为模式、Memory 版本分组；通过实际使用关系连接，不给 Memory 强加唯一 rule_code。
- 区分无经验、参考使用、程序直接复用及企业策略直接处理；同一 Memory 在同一次 Run 只有一种最终用法。
- 参考经验可能影响模型结论，但无法仅凭引用证明因果贡献；匹配分数也不等于准确率。
- 技术真假与运营忽略/转交分开比较。标签只有处置状态时，不据此计算技术准确率；未反馈不当作正确。
- 失败、未运行、缺标签、补充样本均有独立计数。每个比率带分子分母，不把失败混入成功质量或悄悄删除。
- 本语料只有已经上报的告警，不能推导未被上游规则检出的总体漏报率；只能在标注样本中测错误忽略或风险漏判。
- DEV 自动忽略为演练处置结果，不代表真实 ZEUS 已关闭；回写、执行成功率不在本轮被证明。
- Token 优先取 Provider usage；缺少时区分估算/未知，不填 0 冒充免费。金额无价格依据时不估造。

Run 层保存 Base、Memory、Tenant Policy、Effective、模型调用/缓存、每步耗时和总耗时。
直接处理无 Base 模型结论时保留 skipped，不造一个相同 Base 来计算提升。
当前生产总览习惯取每告警最新 Run，批次报告则必须取该轮固定的 Run，不能直接挪用最新总览当历史轮次结果。

### 10.3 如何证明经验带来提升

第一批和第二批不是相同告警，不能直接比较它们的准确率后声称是 Memory 的贡献。
Base 也可能已读取 context-only Memory，并非无经验基线。
主流程先验证复用可用性与成本；另经确认在内网 Mac DEV 选少量第二批样本做成对对照：固定事实、模型与策略，
分别关闭/启用经验检索，记录不同 Run。该测试有额外模型调用，不默认把第二批全量再跑一次。
使用缓存的成对测试只能代表固定事实下的增量，首次全流程成本另列。

## 12. 验证用例与分阶段交付

阶段属于本专项实施顺序，不新增与 roadmap 冲突的全局任务编号。不得一次提交所有改造后才让用户验收。

| 顺序 | 交付内容 | 完成标准 |
|---|---|---|
| 先：性能 | 前端预构建、列表/分组有界查询、导航状态、轻量健康检查 | 达到第 3.4 节目标或明确剩余瓶颈，用户实际切页认可；无清库/真实模型调用 |
| 再：数据与页面 | 名单生成/核验、批次过滤、移除固定推荐演练 | 全数据守恒、两批互斥、标签不泄漏、页面只读取当前批次 |
| 再：后台执行 | 共用持久任务、幂等/续跑、并发、网页与脚本结果一致 | 隔离模拟中断后可恢复，跨入口不重复运行，旧 Worker 不消费演练任务 |
| 再：经验闭环 | 第一批候选来源、草稿与审核、经验快照、第二批无自动学习 | 未批准不启用；两批环境相容；暂停经验不被快照复活；新行为仍正常研判 |
| 再：报告与复测 | 固定轮次统计、CSV/报告、定向重跑与前后比较 | 逐条可追踪，同一轮统计不随后来重跑漂移，来源与分母清楚 |
| 最后：内网实操 | 更新 Runbook/交付，清理指定 DEV 数据，5 -> 50 -> 已批准范围 | 内网模型/网页/脚本实测通过后才扩大；失败可续跑，不重复搬数据 |

必须覆盖的聚焦回归：

- 打乱输入顺序、同时间不同 ID、同 ID 重投，名单与去重仍稳定；时间异常样本保留可查。
- 原静态大组被语义核对拆小后，解释候选不足，不把不同模式硬合成 5 条。
- 人工提前提炼与自动达标并发发生，不产生重复待审对象；确认的窄范围不压住范围外新样本。
- 第一批审核与批跑同时进行，后续独立样本不会被新 Memory 抢先直接处理，也不重复生成已覆盖候选。
- 第二批精确复用、context-only、新行为、无经验、相反经验和企业策略优先，均与单条 Runtime 一致。
- 同告警网页/CLI 并发、响应丢失后重交、服务重启、任务超时、Run 已落库但观察未完成，可审计恢复。
- 模型完成前中断、完成后保存前中断，分别记录成本不确定性；最终结果和 Pattern 观察不重复累计。
- 批跑期间审核、编辑草稿和页面查询不被 SQLite 长事务阻塞；超过一万条结果仍能准确查看最早告警。
- 第二批使用记录完整，但不自动形成新候选；人工提炼后只能进入后续轮次的可检索经验集合。
- 暂停/废止快照中经验时不继续直接复用；变更后开启新轮，旧结果仍可比较。
- 模拟 Provider 返回 usage 缺失、超时、限流和结构错误，成本/失败分类不失真，批次不无限重试。
- 历史语料任务无 ZEUS callback/真实动作；有真实模型不等于其他能力真实。

外网测试只用隔离 SQLite、模拟模型和浏览器 fixture；不安排真实模型试跑。真实调用全部留到内网 Mac DEV，先批准范围，再做少量验证。
每次正式实验遵循 `soc-experiment` 记录 upstream commit、应用版本、模型、config/data hash、
Prompt/Profile、硬件、命令、指标、Mock/真实边界及产物位置；本方案不把未执行的验收写作通过。

## 13. 实施前保留的决策与明确不做

已经明确：性能先行；两批脚本为主；按组内时间划分；小组/单例保留；旧数据待重置；
