# AI SOC Agent 项目月报草稿

> 状态：临时草稿
> 更新日期：2026-09-04
> 使用说明：可直接摘录到月报或邮件；准确率、节省工时和生产自动化率尚需内网 Shadow 数据验证，不应将历史运营处置标签直接表述为独立真值。

## 一、项目概述

本月完成了 AI SOC Agent 最小可用产品及核心闭环建设。项目不只是调用大模型分析告警，而是将多源告警接入、字段解析、事实重建、模型研判、经验复用、企业策略、人工反馈和审计追踪整合为一套可治理的安全运营系统。

项目核心目标是：**把一次性的告警研判结论，转化为可复用、可校验、可持续更新的组织安全经验，从而减少重复研判，提升结论一致性，并反向推动上游规则降噪。**

## 二、已经完成的功能

### 1. 多源告警统一接入

- 支持 NDR、NIDS、EDR、HIDS、SIEM、威胁情报等来源。
- 优先解析告警 `message`，缺失时使用结构化字段补充。
- 完整保留原始告警，并记录每个标准字段的来源和可信度。
- 平安专属字段由独立 Adapter 转换，通用 SOC Runtime 不与某一家厂商的数据格式绑定。

### 2. 标准化 SOC 研判流水线

- 完成实体提取、事实重建、攻击场景识别和证据目录构建。
- 完成网络方向、攻击者、受害者和响应目标的角色裁决。
- 构建有界、压缩、可引用的模型上下文，减少重复日志和无效编码造成的 Token 浪费。
- LLM 输出异常时支持格式修复和局部降级，不因一个可选字段错误丢失已经有效的核心结论。
- 每个阶段记录输入、输出、状态和耗时，支持重放和复盘。

### 3. 完整的决策演变记录

系统分别保存：

```text
模型原始判断 Base Decision
  -> Memory 经验调整
  -> 企业专属策略判断
  -> 最终结论 Effective Decision
  -> 动作授权与执行结果
```

因此可以清楚回答：模型最初如何判断、使用了哪条经验、哪项企业策略改变了结果、最终为什么这样处理，以及外部动作是否真正执行成功。

### 4. 受治理的经验 Memory 系统

- 通过规则标识粗定位，再通过行为指纹区分同一规则下的不同攻击场景。
- 不再把每条告警直接写成一条低质量 Memory，而是先形成去重后的 Pattern Observation。
- 支持重复模式自动聚合，也支持运营人员对单条高价值告警立即提炼经验。
- 支持 AI 草拟、人工审核、确认、启用、停用、修订、失效和使用历史追踪。
- 区分“仅供模型参考的相似经验”和“精确匹配后可直接复用结论的经验”。
- 新告警与既有 Memory 结论冲突时保留前后结果，可进入复盘和版本修订，而不是覆盖历史记录。

### 5. 高质量标准经验

每条正式 Business Lesson 使用统一结构，包含：

1. 检测场景。
2. 实际观察到的业务事件。
3. 最终安全结论。
4. 业务判断依据。
5. 精确适用条件。
6. 允许泛化的边界。
7. 经验失效条件。
8. 后续处置建议。

该结构将个人口头经验转化为团队可以理解、审核、检索、复用和持续维护的标准答案。

### 6. 运营工作台与过程可见

- 已实现告警研判演练、完整 Runtime Trace、Memory Center、经验审核、运营总览和动作审批页面。
- 支持查看原始输入、Adapter 转换、标准化结果、模型输入、模型输出、证据引用和最终决策。
- 支持查看 Memory 的来源、适用条件、版本、当前状态和实际使用记录。
- 支持多条不同告警并行处理；同一个 `alert_id` 重复点击时由服务端防止重复执行。

### 7. 可插拔能力体系

| 能力 | 职责 |
|---|---|
| Adapter | 将不同厂商字段转换为统一协议 |
| Skill | 描述某类告警应该怎样分析 |
| Enterprise Knowledge | 保存企业稳定、受治理的已知事实 |
| Memory | 保存运营审核确认的历史经验 |
| MCP / Provider | 查询资产、威胁情报、安全标签或调用外部系统 |
| Policy | 决定企业允许如何处置及是否需要审批 |
| Lead/Sub Agent | 支持运营人员进行开放式调查和专家能力路由 |
| Runtime | 管理固定流程、状态、证据、重试、持久化和权限边界 |

这些能力各自配置、版本化和审计。更换告警厂商、企业知识、工具系统或运营策略时，不需要重写通用 Runtime，也不会把全部逻辑堆进一个难以维护的大 Prompt。

### 8. 上游规则分析与降噪基础

- 已形成 `Rule Code -> 行为模式 -> Memory 版本` 的分析路径。
- 可以统计不同规则的告警量、历史忽略/转交分布、模型调用、Token 消耗、Memory 使用和结论冲突。
- 同一个 Rule Code 下可以区分 OpenVPN、PLC 漏洞、HTTP 行为等不同 Pattern，避免一条误报经验让整条规则失效。
- 可识别高频、同质、长期误报且消耗大量算力的告警模式，为上游 Flink/SIEM 规则优化提供依据。
- 当前规则改进建议保持只读，不自动修改上游规则。

### 9. 旧系统兼容与内网部署

- 已兼容 ZEUS 原有任务提交和状态查询协议，减少上游系统改造量。
- 已实现持久任务、有限并发 Worker、幂等处理、失败恢复、Callback Outbox 和调用审计。
- 已提供 Apple Silicon Mac 无 Docker 部署方案、DEV/STG 环境切换及完整内网交付包。
- 内网已验证模型调用、ZEUS 待审状态查询和 Runtime Worker。
- ZEUS 上游真实发起、最终结果回写和旧页面回读仍需联合联调后关闭验收门禁。

## 三、项目价值

### 1. 经验复用

运营专家确认一次同类行为后，后续精确匹配的告警可以复用其结论和依据，不再由每位运营人员从头阅读日志、重复研判。

### 2. 经验对齐

通过统一的 Business Lesson 结构、适用范围和失效条件，将分散在个人经验、Prompt、聊天记录和历史点击中的知识转化为团队共同使用的标准口径，减少不同人员之间的判断差异。

### 3. 上游降噪

系统不仅处理已经产生的告警，还能按规则和真实行为模式识别重复告警、长期误报及无效算力消耗，帮助上游检测规则进行针对性优化，从源头减少低价值告警。

### 4. 过去与现在对比

每次研判都保留模型原判、历史经验、企业策略和最终结论，可以比较过去经验对当前判断产生了什么影响，并统计经验使用后是否被运营人员再次改判。

### 5. 可维护

厂商适配、研判方法、企业知识、历史经验、实时工具和处置权限分层管理。新增厂商或能力主要增加 Adapter、Provider 和租户配置，不需要反复修改核心流程。

### 6. 过程可见

告警从原始输入到最终结论的每一步均可以查看、回放和审计。系统失败时也能定位是字段解析、模型调用、证据校验、策略还是外部接口问题，而不是只看到一个模糊的“研判失败”。

### 7. 经验有时效

Memory 具备有效期、复核周期、版本和失效条件。业务环境变化后可以暂停旧经验并创建修订版本，避免过期结论长期影响新告警。

### 8. 快速经验复用

系统既能在固定窗口内自动聚合同类告警，也允许运营专家在发现高价值案例时立即提炼；AI 可以根据当前告警和审核方向草拟完整 Business Lesson，专家只需要校对和确认。

### 9. 高质量标准答案

经验不再只是“忽略”或“转交”两个干巴巴的状态，而是包含发生了什么、为什么这样判断、适用于什么情况、何时不得复用以及应该怎样处理的完整标准答案。

### 10. 持续化运营反馈

运营人员后续修改告警状态或给出原因时，系统可以记录模型结论与最终处置的差异，并将其用于 Memory 复盘、版本修订、质量评测和规则优化，形成持续运营闭环。

## 四、阶段成果

- 已纳入 `4,343` 条历史告警。
- 覆盖 `7` 类 canonical source。
- 覆盖 `310` 个规则标识并形成 `1,280` 个行为组。
- `4,082` 条告警可形成标准行为指纹。
- `3,069` 条满足当前决策型 Pattern 的基础条件。
- 已走通“告警研判 -> Pattern 聚合 -> Candidate 审核 -> Business Lesson -> 新告警复用”的完整产品闭环。

历史语料中有 `3,566` 条带运营处置标签，其中 `2,798` 条忽略、`768` 条转交。这些数据可以用于流程对照和产品验证，但属于历史运营结果，不等价于独立、具名审核的安全真值，因此当前不直接宣称生产准确率。

## 五、建议后续量化指标

- 重复告警平均人工处理时长及下降比例。
- Memory 精确命中率、复用率和命中后的人工改判率。
- 相似经验作为上下文后对模型结论和复核率的影响。
- 各 Rule Code 的告警量、误报分布、真实风险检出和算力消耗。
- 上游规则优化前后的告警量及有效告警占比。
- 自动忽略率、错误自动忽略数量和人工转交检出率。
- 模型调用次数、Token、P50/P95 延迟、失败率和重试率。
- Candidate 产生、审核、启用、修订和失效的周期。

## 六、下一阶段

1. 完成 ZEUS 上游真实发起、结果回写和旧页面回读联调。
2. 接入真实资产、威胁情报和安全标签等只读能力。
3. 由少量运营专家审核代表性样本和高价值 Candidate，建立可衡量的质量基线。
4. 进入 Shadow，统计研判一致性、人工复核率、Memory 有效命中率、耗时、成本和错误自动化数量。
5. 根据真实数据优化高噪声 Rule Code，并评估减少的告警量和算力消耗。
6. 达到质量门后进入有限试点，不直接替换现有生产处置流程。

## 七、汇报收口

> AI SOC Agent 的价值不是替代运营人员做一次判断，而是把每次研判沉淀成全团队可复用的标准经验，并通过持续反馈让模型、经验和上游检测规则共同演进。
