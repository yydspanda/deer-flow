# 内网 Mac：重新配置并全部重跑

先安装包含此功能的新版应用，按交付包的保留数据升级手册启动服务。两批都可使用页面按钮，无需执行数据库清理命令。

## 第一批忘记开启语义核对

1. 在部署 Mac 打开 `http://localhost:2026/workspace/soc/corpus-validation`。暂停第一批；如果第二批也在执行，一并暂停，等待两批运行中均为 **0**。
2. 切回 **第一批**，点击 **重新配置并全部重跑**。
3. 在弹窗中打开 **语义核对**；通常不勾选 **重新核对事实**。其余设置按本轮计划确认，例如企业策略关闭、最大并发16（并发在运行设置中单独保存）。
4. 点击 **全部重新运行**。包括成功、失败、未运行在内的整个第一批都会按新设置运行，列表筛选不缩小范围；完成数从新任务重新统计。
5. 第一批完成后，重新 **审核经验**，再到第二批确认设置并 **开始验证**。

旧结果、候选和已审核经验均保留，不会被删除或自动废止。新一轮独立积累，不计入旧经验；审核入口和第二批经验快照使用本轮来源。第二批旧任务停止调度，旧结果仍可从运行历史查看，当前第二批恢复为未运行，需要重新验证。即使新旧设置相同，整批重跑也会重新积累；普通单条重跑仍沿用当前这一轮的积累范围。

仅打开页面开关再点 **继续**，不会改写已排队任务的设置；要将整个第一批改为语义核对开启，必须使用上面的整批重跑按钮。

## 只重跑第二批

1. 在部署服务的 Mac 打开 `http://localhost:2026/workspace/soc/corpus-validation`，切到 **第二批**。
2. 如果仍在执行，点击 **暂停**，等顶部 **运行中 0**。已经提示 `configuration_changed` 且运行中为 0，可以直接下一步。
3. 点击 **重新配置并全部重跑**，确认弹窗中的运行设置。需要与已核实的第一批一致时：**语义核对打开**，**重新核对事实不勾选**，**企业策略、安全软件路径策略、LLM 策略建议全部关闭**。
4. 点击 **全部重新运行**。系统重新排队整个第二批，包括以前成功、失败和未运行的告警。当前搜索、同类组和第二批范围筛选不会缩小这次执行范围。
5. 看顶部的完成、运行中、剩余和失败数；这些按每条告警的新任务重新统计。需要只看正在执行的告警，将 **运行状态** 选为 **运行中**。之后正常使用暂停、继续。

旧结果保留在告警详情的运行历史中，可点击查看。第一批积累、人工审核及已有经验不重建；新任务读取当前已审核开放的第一批经验。运行设置相同不保证模型输出逐字相同。

若提示先审核经验，请回第一批点击 **审核经验**，确认并开放经验后再操作。若提示第二批已有新提交，刷新弹窗并确认当前设置后再提交。网络失败时直接点击重试，系统会复用同一次提交，避免重复创建整批任务。

局域网同事仍可运行、暂停及全部重跑，但只能使用服务器已经保存的配置；修改配置请在部署 Mac 的 localhost 页面操作。最大并发仍在 **新任务运行设置 → 最大并发** 单独调整。

## 定向复测与原整批任务同时存在

页面进度按每条告警的最新任务汇总，可能涉及多个轮次。**新任务运行设置** 显示新提交使用的开关；继续已有任务时，各轮仍使用自己保存的配置。它不是所有活动任务的实际设置总览。

定向复测只使用对应 `round_id` 的 `status`、`pause`、`resume` 命令，不使用页面批次“继续”。旧版页面会把其他未完成轮次一起恢复；新版会拒绝这种扩大范围的操作，单条重跑不会解除保护。明确选择整批重新配置重跑后，才按新的整批任务继续。

如果旧版页面已经恢复了其他轮次，先暂停并等待运行中为 0。通过 `GET /api/soc/dev/corpus-workbench/rounds/{round_id}` 查看该轮的 `round.options`、`round.dispatch_alert_ids` 和任务计数，确认目标轮次及其实际配置。已有结果和审核经验无需删除。

**以下恢复参数仅适用于支持它的代码，且该轮冻结的代码、配置和经验快照仍须匹配。此前交付的归档不支持它；升级本身会改变代码快照，不能据此承诺升级后恢复旧轮次。** 满足快照要求时，如需让原整批轮次继续覆盖自己原定的全部样本，使用现有 CLI 的 `resume --round "目标ROUND-ID" --restore-full-scope`。这只恢复原轮次的调度范围，保留冻结设置与已完成结果；它不会重试终态失败任务，失败项仍使用原有 `retry-failed` 命令显式处理。普通 `resume` 保留原调度范围，不能保证补齐曾被排除的任务。若出现 `configuration_changed`，保持原记录并另行确认新轮次方案，不修改旧快照绕过校验。

定向复测报告和整批报告各自按固定轮次导出。不能把页面最新结果汇总当作某一套配置的完整报告，也不能把不同配置的复测结果直接替换进同一阶段报告。

## 旧版本因多文件告警而停止

旧版本遇到多文件告警时，可能因附加事实超过 40 条而归一化失败，随后被批处理误报为 `Runtime returned a different alert identity`。再次继续时的 `snapshot changed; create a new round` 是旧版对已停止轮次的通用提示，不能据此判定设置或经验发生了变化。应以该次 Run 的 `failure` 为准。

修复版将 canonical 附加事实容量提高到 400，保留全部来源；模型单次补充仍限制为 40 条。输入与固定样本核验一致的归一化失败只记录为单条失败，其他告警继续执行。真实身份不一致仍停止轮次。

已经停止的旧轮次不会因安装修复版而自动解锁。需要完整阶段报告时，安装修复版后按上面的 **只重跑第二批** 操作，保留第一批及已审核经验，不清库；第二批已完成的样本也会重新执行，旧结果留在历史。只建立剩余样本的补跑轮次可以补齐页面结果，但现有报告按固定全量轮次读取，不能直接将这些轮次拼成完整阶段结论。
