# 第二批效果统计与分批抽查

适用于第一批已完成经验积累和审核、第二批已运行结束的内网 Mac DEV。
工具只读取本地数据库，生成报告和 Excel 可打开的 CSV；不调用模型、不重跑告警、
不修改数据库或经验，不需要重新安装应用或修改服务配置。Python 3.12 即可运行，无需安装依赖。

## 1. 将工具复制到 Mac

将提供的整个 `VALIDATION-REPORT-TO-TRANSFER` 文件夹复制到 Mac 的 Downloads，最终位置是：

```text
$HOME/Downloads/VALIDATION-REPORT-TO-TRANSFER/
  soc_pingan_validation_report.py
  soc_validation_report_data.py
  soc_validation_report_render.py
  README.md
  SOURCE.json
  SHA256SUMS
```

这个文件夹放在项目外，运行时通过 `--root` 指定已安装的项目。无需将文件覆盖进 `deer-flow`。

## 2. 执行统计

先确认第二批没有运行中的告警。统计期间请暂缓提交重跑和修改经验审核；服务可以保持运行。
复制下面完整一块到 Mac 终端：

```bash
bash <<'BASH'
set -euo pipefail
cd "$HOME/Downloads/VALIDATION-REPORT-TO-TRANSFER"
shasum -a 256 -c SHA256SUMS
python3.12 soc_pingan_validation_report.py --root "$HOME/deer-flow"
BASH
```

终端会持续显示读取阶段与分页进度。大数据库需要等待，不要因为暂时没有最终结果就重复运行。
完成后终端打印报告目录，位于项目的：

```text
backend/.deer-flow/soc-internal-validation/second-batch-report-时间-唯一编号/
```

每次运行新建目录，不覆盖已有报告或填写过的抽查表。
`manifest.json` 是完成收据，包含各文件的 SHA-256、工具文件哈希和本次轮次标识。
若输出中没有该收据，则不是完整报告。

如果工具已经随新版源码安装，也可从项目根目录执行：

```bash
cd "$HOME/deer-flow" || exit 1
python3.12 scripts/soc_pingan_validation_report.py --root "$HOME/deer-flow"
```

## 3. 查看结果和填写抽查

| 文件 | 用途 |
| --- | --- |
| `REPORT.md` | 先看总体结果、两类样本的指标、数据覆盖与限制 |
| `groups.csv` | 同类组对照：第一批、审核状态、第二批结果和经验使用 |
| `alerts.csv` | 第一批与本次第二批的逐条运行摘要 |
| `candidates.csv` | 候选来源、审核状态；当前状态与运行时可证状态分开 |
| `memories.csv` | 实际使用经验及去重后的告警覆盖情况 |
| `differences.csv` | 全部待核实差异；差异不自动判定为错误 |
| `review.csv` | 按同类组分批的抽查工作表，补充判断、原因、处理建议、审核人和时间 |
| `followups.csv` | 主轮次之后的补充运行；不覆盖主报告结果 |
| `report.json` | 可复核、可进一步计算的结构化摘要 |
| `manifest.json` | 完成标记、统计范围及文件校验值 |

CSV 使用 UTF-8 BOM，Excel 可直接打开。请将填写后的抽查表另存为 `review-filled.xlsx` 或
`review-filled.csv`，保留原始导出以便核对。反馈仅保存在表格中，不自动修改经验、告警结论或启动任务。

向领导汇报时，先看 `REPORT.md` 中两类样本的完成情况、经验覆盖与实际使用、历史处置一致性，
再结合人工抽查说明主要差异及改进方向。尚未抽查的数据不能表述为准确率或已经证实的效果提升。
时间仅保留逐条研判耗时及两类样本的 P50/P95，作为辅助数据；本期不增加按经验使用方式的耗时比较、
阶段耗时汇总或整批排队／暂停时间统计。

默认每批 20 个同类组。先检查风险和匹配差异，再检查未标记差异的固定随机抽样。
定向与随机抽样会分别标明；组数与实际抽查告警数分开，不把定向抽查结果当作全量准确率。
如需每批 10 组，在同一命令末尾加 `--groups-per-batch 10`。

第一轮先补充三件事：

1. 判断是否合理：合理差异、需要修正、证据不足或暂未确认。
2. 写明原因：按事实自由填写，不限定红队、演练、JDWP 等预设类别。
3. 写明下一步：无需处理、补充证据、调整经验或检查系统。

## 4. 统计口径

- 自动选择唯一实验中最新的、实际名单覆盖第二批全部成员的全量轮次。最新单条重跑不会取代整批。
  若最新全量尚有未完成任务，停止并说明原因，不回退选择更早的已完成轮次。
- 主报告固定到该轮次的 Job/Run，后续其他轮次作为补充；第一批参考记录按主轮次开始前的来源选择，
  无法证明当时状态的字段保留未知。
- 保留原始 `验证经验复用` / `其他测试告警` 划分。主动放弃沉淀不会更改第二批分组，
  整体覆盖率不移除这些样本。第一批与第二批不是相同告警，比例差不能直接证明经验提升。
- 同类组、Pattern、候选与 Memory 不是一对一。只按已有来源关系关联；一组允许多个审核状态和结论，
  不凭名称相似或同组关系推定某条经验适用。
- 第二批冻结经验快照可以证明纳入的 Memory ID/版本。当前候选或 Memory 状态不是运行时状态；
  缺失历史证明时标记无法还原。放弃候选不等于否定原告警判断。
- 经验参与结论优先于仅作参考，逐告警去重。真正跳过主模型另列；仍可能消耗语义核对等模型用量。
- 当前网页放弃候选保存的是通用理由。工具不从标题或状态猜测红队、演练、证据不足等具体原因，
  由运营抽查后补充。
- 历史忽略/转交的一致性不是安全准确率。缺少可用历史标签或独立人工真值时保留未知；
  没有反馈不等于判断正确。语义核对改动数量不证明改动正确。
- 历史标签从已部署的语料 JSON 索引读取，必须匹配实验冻结的文件哈希和每条成员的内容哈希/同类组。
  工具不读取 PKL。索引缺失或验证不通过时明确报告标签不可用，其他结果仍可统计；
  非标准安装位置可用 `--corpus-index` 指定该 JSON 文件。
- 数量、分母、未计量用量和数据缺失分开报告。仅汇总选定 Run 已保存的用量；历史失败尝试可能未计入，
  不宣称失败调用费用已全部计入，也不推算人民币成本或因果节省。

## 5. 工具停止时如何处理

| 提示 | 操作 |
| --- | --- |
| 未找到数据库 | 检查项目实际位置，修改 `--root`；工具不会创建数据库 |
| 存在多个实验／无法确定全量轮次 | 根据工具列出的 ID 核对后显式指定 `--experiment` 或 `--round`；不要猜 ID |
| 全量轮次尚未结束 | 等待当前任务结束或检查未完成任务，不改用旧轮次凑结果 |
| 数据库繁忙／查询超时 | 本次报告不成立。稍后重试；仍失败时保留报错用于定位，勿修改日志模式或执行数据库维护命令 |
| 读取期间数据库发生变化 | 稍后在无任务和审核修改时重试；工具拒绝混合不同时间的数据，不会修改已有结果 |
| 数据库字段不兼容 | 保留完整提示，核对工具与已安装版本；工具不会自动迁移 |

只读连接使用短查询并及时释放游标；单次查询设有时间上限。SQLite 的读取仍可能与写入竞争，
因此不承诺在持续写入的大数据库上零等待。工具不持有跨全部读取过程的长事务，不做整库备份或扫描完整研判正文。

报告包含内部告警、经验标识及审核摘要，先在内网查看。外部协助分析时按内部允许范围提供汇总，
无需传输整个数据库或原始告警日志。

## 6. 排除整条运行失败与语义核对失败，生成效果汇报版

将新的整个 `VALIDATION-EFFECT-TO-TRANSFER` 文件夹复制到内网 Mac 的 Downloads。
保留原始报告，执行以下命令生成新的效果汇报版：

```bash
bash <<'BASH'
set -euo pipefail
cd "$HOME/Downloads/VALIDATION-EFFECT-TO-TRANSFER"
shasum -a 256 -c SHA256SUMS
python3.12 soc_pingan_validation_report.py --root "$HOME/deer-flow" \
  --exclude-failed --exclude-semantic-failed
BASH
```

默认仍选择最新全量第二批轮次。如需与某份原始报告保持同一轮次，在命令末尾加
`--round` 和该报告中的完整轮次 ID；后来重跑成功的结果仍另列，不替换固定轮次。

输出到新的 `second-batch-effect-report-时间-唯一编号` 目录。`REPORT.md` 注明原范围、两种失败数、
重叠数、去重排除数和纳入数；总览、经验使用、历史处置对照、用量、同类组第二批统计及抽查均按排除后的范围重算。
`excluded_alerts.csv` 单独保留被排除告警及其任务标识，方便对照，原报告和数据库不变。
语义核对状态为 `failed` 的告警会排除，即使整条任务完成；`partial`、`skipped` 等状态不会仅因语义状态被排除。
两种排除条件可以单独选择：若仅需排除整条运行失败，只保留 `--exclude-failed`。
效果汇报版不作为全批运行成功率报告，也不代表被排除告警已经查明正确或错误。
