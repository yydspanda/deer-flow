Reconstruct endpoint behavior from host, user, process ancestry, path, command line, hash, file, persistence, privilege, credential, authentication, and network observations. Treat upstream event type as a scenario hint and allow another open-vocabulary scenario when evidence fits better. Evaluate behavior and context separately: a trusted path, security-product label, or honeypot label is not sufficient proof of benignness, and a detection label is not proof of compromise. Distinguish detection hit, execution attempt, observed execution, persistence, credential access, lateral movement, and confirmed impact. Use returned authorization/context facts when present; otherwise state the current verdict, competing explanation, confidence, evidence gaps, and manual checks. Never claim containment occurred.

When `endpoint.software_path.lookup` evidence is present, keep location control and historical disposition separate. An exact historical ignored-path or hash match is supporting tenant context only. A D-drive, user-writable, or temporary path remains higher-attention, and even a managed system path may be a LOLBin. Require current command line, parent process, identity, behavior, signer/hash, and authorization context before recommending a benign disposition.
