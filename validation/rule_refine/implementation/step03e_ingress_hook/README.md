## 入口与计数口径

源码 ZIP 中 `service/routers/workflows.py:135` 的 `flow_task_router` 是同步函数，由 FastAPI 线程池运行。监测在任务参数构造完成后、`create_work_flow_task` 前调用，沿用现有 `/workflow/task` 鉴权和请求模型。

统计是**本服务接收并成功登记的去重告警量**。原任务随后创建失败也不回滚已登记观察；重发由计数器去重。监测失败、容量满、预算耗尽时登记可能不完整，必须记录原因，不能称 ZEUS 全量或成功任务总量。

只观察 `app_code=zeus` 且 `flow_id=alert_agent` 的请求。配置归属仍由统一查询契约返回；当前 CSV 是 mock 提供器，未来 ZEUS API 替换其实现。live 计数时间仍为 `redis_observed_at`，不声称精确 HTTP 到达时间。

## 失败、耗时与容量

- 默认关闭；关闭时不加载 CSV 或 Redis 配置。监测异常只记类型与结构化原因，不输出原始告警、异常消息或连接凭证。
- 每个 API 进程最多同时监测 4 个请求，饱和时不新增排队；记录未登记。该限制不等于所有 API 进程的全局上限。
- 最多处理一个请求的 8 条唯一规则；1 秒软预算用来停止开始后续规则计数。正在执行的计数不会被虚假取消，耗时可能超过 1 秒。
- 专用 Redis 客户端复用现有配置地址，连接/读超时 0.5 秒，关闭客户端自动重试，连接池上限 16，WATCH 竞争最多尝试 3 次。最多 4 个请求各占两条计数连接。沿用无 Lua 的事务算法。
- 初始化失败退避 30 秒后再尝试，避免每条请求重复解析故障配置。配置切换后需重启 API 进程。
- 监测模块出错不会改写原业务返回或吞掉原任务创建异常；开启后会增加同步请求耗时，不能声称无延迟影响。
- 生成的 pending signal 持续保留；本步不派发分析、不确认删除信号。后续按持久信号驱动分析，而非只依赖一次日志。
