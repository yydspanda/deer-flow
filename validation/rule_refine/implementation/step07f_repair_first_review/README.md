## 调整内容

- 生成应先表达具体操作，不停留在进程、账号、地址等主体属性；不预设每个topic的字段模板。
- 复核按“检查草案 → 从已有原文尝试具体修正 → 核对实际范围 → 给出候选或说明无法修正的原因”进行。缺少同一主体下的反例样本，会限制验证结论，但不会自动禁止提出更具体的候选。
- 字段用途与条件范围分开：进程名称可以是事件字段，只按进程名称过滤可能过宽；不能把它错误解释成规则命中结果。
- 是否会关闭整条规则，依据 `rule.configuration`，不能从检测名称或当前样本全都相同推断。JSON表达式仍决定实际范围，业务确认前提不能补上JSON缺失的限制。
- 允许在明确适用前提下提出供运营确认的候选；不要求在建议阶段证明所有同类活动均无害。已知无法接受的范围且缺少收窄材料时，`insufficient_evidence`仍有效，不强迫返回proposal、不编造父进程或任务来源。
