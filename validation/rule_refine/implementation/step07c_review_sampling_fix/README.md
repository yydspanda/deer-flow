# 第7C步：为AI复核保留新的告警原文

第7B内网真实结果已成功生成建议，但复核重复了生成阶段的全部28条当前告警，新增原文为0。旧取样器把草案引用的全部原文列为必须保留，挤掉了尚未展示的告警。本步骤修复取样优先级，不改变已完成建议。

## 内网执行

打开 [INSTALL-COMMAND.sh](INSTALL-COMMAND.sh)，将整个文件复制到内网终端执行。脚本先运行56项离线检查，再备份并安装3个运行时文件和1个新测试文件。重复执行会识别已安装版本；存在未知源码修改时保留原文件并停止。

安装成功后，按原来的方式停止并重新启动 `local_run.sh`，让后台worker载入更新。脚本不会自动重启服务，也不会调用模型或重新补数。模型选择、总输入预算、输出参数、DEV数据库以及既有报告不修改。

安装本身不调用模型，已完成任务继续保留原结果。用户已回传安装成功：56项测试通过、4文件更新、installed_state_verified=true，备份目录为 `surge-review-sampling-fix-n8_zwet_`，并确认 `local_run.sh` 重启成功。此处是用户回传记录，不表示助手已访问内网进程。

**新版真实手工实测已回传。** 用户执行原[第7B真实CSV脚本](../step07b_real_csv_acceptance/CHECK-REAL-CSV.sh)，目录 `surge-real-csv-runtime-tcpan7hp`：生成28当前+11历史，复核26当前=13新增+13原引用+11历史，原引用15个未展示；两阶段实际SDK请求2次，累计41个不同当前告警。`received/proposal`、`ai_review_completed=true`，说明新取样已进入实际调用；14新/13旧只是下述离线对照结果，非固定数量。旧报告保留，本次是手工验证，没有验收后台自动触发。

该轮AI改为仅按子规则名过滤；正文又称仅限低级别并保留命令/父进程变体，JSON并未表达这些限制。取样修复成功不等于所有建议承诺正确；范围分析及tokens见[第7B结果记录](../step07b_real_csv_acceptance/README.md#内网结果已回传)。记录原报告，不静默改写或自动应用。

## 具体变化

1. 先从未展示的当前告警中找到一条能完整放入现有预算的原文，避免过大的首条新候选失败后，又由旧引用占满预算。
2. 此后交替加入原引用与新告警，仍按时间分散取样，并优先考虑AI提出的补样请求。一侧没有可用材料时，剩余空间给另一侧；没有固定样本条数或新旧各占多少的硬额度。
3. 共享历史继续保留。预算不足时沿用只缩减未引用、较旧历史的机制；每次按完整请求计算预算，包括字段目录、草案和审计说明，不截断日志。
4. 草案及其引用列表完整保存。请求中的 `draft_reference_visibility` 标明哪些引用原文在本轮展示、哪些没有展示；最终回答仍只能引用本轮实际展示的ID，不把旧草案文字当原日志证据。
5. 新报告显示“新增原文／复用原引用／未展示引用”数量。没有未见告警，或在保留草案和历史后任何完整新告警都放不下时，明确写成同材料复核，不虚报新增证据。

仅复核提示版本升为 `rule-surge-runtime-review-v2`；独立生成版本不变，解析器不放宽，SDK调用次数仍最多2次，不执行程序过滤试算，不增加输出token上限。
