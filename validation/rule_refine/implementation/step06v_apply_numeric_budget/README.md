## 全链路限制复核（6V仍未解决）

以下依据6V清单对应源码、只读CSV统计与人工数据复现；没有内网执行、真实模型调用或业务数据库/Redis操作。

| 环节 | 当前限制与实际行为 |
|---|---|
| 读取任务 | 最多20个告警ID、100条任务记录、返回数据8MiB；行数或总量超过会整次失败。单告警1MiB，旧回答16KiB；SQLite连接等待2秒，查询进度检查5秒 |
| 组装材料 | 规则允许512KiB，单告警/日志组1MiB；最多1000个hit、同规则100条日志。单告警中相关日志无效等可导致整个样本被排除 |
| JSON结构 | `_encode`每次都限制10000节点/32层，字典键和值均计数；该限额重复用于单告警、整个材料、保存包装。节点多但字节小也会失败 |
| 候选与取样 | 总候选3MiB、最多20告警；最终messages128KiB，每告警最多3条日志，顺序取完整日志。不是20条全部保证入模；128KiB也不是模型的能力上限 |
| 规则配置 | 分析前规则投影超过32KiB会返回无可用材料。实际911条CSV中，3条投影超过此限；最大约61.9KB。统计只输出数量，没有导出配置正文 |
| 旧研判参考 | 读取/组装超过16KiB省略；入模前超过2KiB再次整份省略。正常长回答可能没有参与规则建议分析，省略有计数，但不会整次报错 |
| 条件能力 | 只读取顶层原样字段名；字符串equal/contain/notcontain，数字仅equal。不支持嵌套路径、数组/布尔条件、大小比较、正则、网段等。1～32条件、表达式2048字符/256 token/32层；条件值4096字符 |
| 模型回答 | UTF-8总量16KiB；问题/建议/确定性各4096字符；只接受规定结构的JSON或完整JSON代码框。不支持的额外字段等会整份失败，多种原因统一为invalid_model_output |
| 模型请求 | 后台固定240秒超时设置、SDK重试0；代理内部尝试未知。并非绝对240秒墙钟上限，生成请求没有与16KiB接收限额对应的输出预算 |
| 保存记录 | 每份4MiB，但再次施加通用10000节点；可能在模型已经生成之后保存失败 |
| 失败恢复 | blocked/analysis_unconfirmed第一次即暂停。旧失败结果被复用，调度retry reset不重新分析；旧pending不清空时该规则不能新建信号，且pending没有TTL。重启不能自动修复 |
| 材料等待 | 缺任一样本任务会返回materials_pending；普通可重试错误默认60秒间隔、最多3次，之后暂停。不能将它称为模型自动重试3次 |
| 接收监测 | 每进程4个监测请求、每请求最多8规则、1秒软预算、Redis单次0.5秒；超限降级只记日志，无补记队列，因此计数可能低于实际接收量 |
| 触发与调度 | 默认1小时/1000条/3倍、冷却1小时、去重24小时；未满基线时high_volume。当前配置文件没有这些字段，实际沿用写死默认，不能说运营可直接配置。每tick查256作用域、处理1个信号，模型期间持本机锁 |
| 环境与版本 | 后台仅LOCAL+本机SQLite/模型代理。提示词摘要或完整CSV行版本变化会阻止旧建议继续交付；CSV同一行备注等非生效字段改变也会改变版本。当前没有自动新尝试恢复流程 |

本次具体复现：

- 20条人工日志，每条300个短字段，材料仅69,578字节，仍因10000节点在分析取样前失败。
- 20条人工日志，每条237个字段，材料55,736字节，messages74,832字节，假模型回答校验为proposal，但完整包保存再次超节点。这证明字节预算变大无法单独解决跨层限制。
- 3KB旧研判回答整体省略。三段各4096中文字符的回答满足单字段合同，但总计约37KB，被16KiB接收上限整体拒绝。
- 表达式只使用A，额外未使用B无证据：试算只检查A，分析却检查A和B并拒绝，两个消费者不一致。
- 合成513字符rule_name通过前置配置验证，假模型回答后才因建议合同512字符上限失败。当前911条CSV最大规则名91字符，尚未在这份配置中实际触发。
