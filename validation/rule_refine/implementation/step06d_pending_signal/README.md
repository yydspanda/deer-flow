## 行为

- 只读取已有待处理信号，不重新计数。核对模式、命名空间、应用、企业、topic 和规则编码；错误作用域不会进入分析。
- 原入口在创建数据库任务前计数，因此信号出现时，其样本任务可能尚未提交。6B 现在先检查对应应用、`alert_agent` 流程及引用告警的任务行覆盖；缺行返回 `materials_pending`，记录缺少数量，后续调用可重新读取。不会写分析开始标记或调用模型。
- 任务行已经存在但原告警不可用，与缺行区分；无法组成有效分析请求时返回 `materials_unavailable`。部分坏样本仍按 4A 的 partial 规则处理；历史响应只是可选参考。
- 只有 `received` 或使用有效材料形成的 `not_applicable` 可以确认。确认前核对内容寻址的分析存档、完整原信号输入、本任务分析文件、已保存交付结果。旧版零材料结果不会被确认。
- 已保存结果后的交付/确认重试沿用原分析，不重复生成建议。`busy`、材料失败、分析未确认、校验阻断、交付未确认均不调用确认。
- 确认仍用第 3 步无 Lua 计数器的条件删除：只能删除原 signal_id。返回 False 为 `ack_not_applied`，不误删后来信号；异常为 `ack_unconfirmed`、acknowledged=null，删除可能已完成。再次读到空仅说明当前无待处理信号。

## 当前边界

本步使用人工计数器和真实本地文件处理流程，不连接真实 Redis、数据库、模型，不启动线程、定时器或 Celery。接口已串联不代表后台消费已启用。下一步接后台执行与有效业务样本时再验证真实计数器及任务读取。

未到达的任务可能永远不提交；本步保留信号供重试，不自动认定已处理。后续调度需要展示等待原因并设置有界重试/人工处理策略。开始记录存在而分析结果缺失时，继续保留原有 `analysis_unconfirmed` 行为；自动重新生成未实现。此次不迁移之前保存的部分材料记录，等待任务覆盖的新检查作用于尚未开始分析的信号。
